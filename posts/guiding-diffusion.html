All of the ways to guide a diffusion model

15.12.2024

This post aims to explain common ways to guide diffusion models, in order to get better samples out of them.

I'll start by quickly introducing diffusion models and some formalism here, but if you know what is up then just skip this section. This post is mainly written for people who already have a good grasp on deep learning and diffusion, but I'll start with a small introduction to broaden the possible audience of this post.

Let's get right into it. We have some dataset which contains some actual data x and each datapoint has a corresponging condition c. Often, the dataset consists of images and their labels: e.g, an image of a dog (x) and a text label "a dog running" (c). What we want now is to train a magical model that takes in a new text prompt like "a dog biting the ankle of my middle school bully", which then promptly returns an adequate image fitting the input text prompt.

We can do this by training a diffusion model $D_{\theta}(x+n, c)$ on our dataset. Diffusion models are trained by adding some noise (n) to the images and training the model to remove that noise, given the text condition. If we train the model using all noise levels from pure noise to very little noise, we can then during inference start from pure noise (and a text prompt) and denoise it all the way to a clean image.

Let's see what this looks like in pseudocode:

x = n
for timestep in range(0, timesteps):
    x = $D_{\theta}(x, c)$

Simple, right? After this the denoised x is your requested image.

Why do we need guidance?

Now, let's generate a beautiful image using the F-Lite model to see what a text-to-image diffusion model can do:

That might or might not be a "A dog running on a field".

So why does this happen? The best explanation so far I've heard is from the Autoguidance paper: "The training objective of a diffusion model aims to cover the entire (conditional) data distribution. This causes problems in low-probability regions: The model gets heavily penalized for not representing them, but it does not have enough data to learn to generate good images corresponding to them."

The model is forced by training to try be good at everything, and thus turns out be below average in everything. We need to figure out a way to nudge the model towards outputs that it is confident and actually good at generating.

But how to do that? Could we for example train a classifier on good and bad images that would steer the generation process? Yeah, but there are better options.

Classifier-free guidance (CFG)

Instead of training a separate "good images" vs "bad images" classifier, could we use the diffusion model for guiding itself? Turns out we can: the trick is to jointly train an unconditional diffusion model $D_{\theta}(x)$ and a conditional diffusion model $D_{\theta}(x, c)$ and use the uncondtional model to see which way not to go. If we know during generation "which way we should not go" and "which way we should go", we can draw an arrow from the "which way we should not go" to "which way we should go" and then go even more into that direction. This allows us a tradeoff: the more we go into the direction of this arrow, the better our images will look, but the drawback is that we lose diversity if we go too far.

What this looks like during training is that the label (c) is randomly dropped (usually 10%ish). So in the case of images and their labels, the labels would be dropped. During training, if we happen to get a sample that is really noisy and a dropped prompt, then how is the model to know what kind of an image it is generating? Yeah, the model really can't know and will be pretty bad, which is perfect for "which way we should not go".

During inference, we then will go towards our conditional prediction $D_{\theta}(x, c)$, but also away from the unconditional one -$D_{\theta}(x, c)$. We will control the strength of "how far away we should go from unconditional prediction" with parameter w, which starts from 1 (no CFG) and can be increased to infinity. Here's how the inference loop looks for CFG:

x = n
w = scalar [1, $\infty$[
for timestep in range(0, timesteps):
    x = w$D_{\theta}(x, c)$ + (1-w)$D_{\theta}(x, c)$

Let's generate the same "A dog running on a field" image, but this time with a CFG of 6:

Now the image definitely contains a dog running on a field! But as you can see, this isn't without it's tradeoffs. While using CFG, the model decided to use a much simpler overall style (cartoonish) instead of "photoreal" like in the first image. This hints at the model being more confident with simpler styles in general, either due to their innate simplicity or the training data used.

Adaptive projected guidance (APG)

Now, CFG is fine, but what if you really need to crank it up? Let's see our canine image with a CFG of 15:

Damn, shit looks awful. Fortunately, the authors of the APG paper found an interesting trick: you can decompose the CFG-term into parallel and orthogonal components w.r. to the conditional prediction and observe that the parallel component primarily oversaturates the image while the orthogonal components enhances the image.
